# StreamCap 工程盘点与最小改造报告

> 盘点日期：2026-09-11  
> 基线：StreamCap `main` 分支源码，项目版本 1.0.3；用户提供的 `StreamCap_1.0.3_Win_x64.zip` 作为改造前 Windows 成品基线。  
> 原则：本报告只盘点和实测，不修改 `platforms / recording / FFmpeg` 主链路。

## 1. 结论

StreamCap 已经具备直播间增删改、循环监控、开播自动录制、停止录制、多任务调度、快手解析、Cookie 透传、FFmpeg 录制、分段、转码、目录命名、文件浏览、更新检查、桌面/Web 双入口和 Windows 打包能力。这些能力应按 A 原样复用或 B 最小接入处理。

V1 真正需要新增的是两个旁挂模块：

1. 快手官方网页登录、HttpOnly Cookie 获取、Windows DPAPI 加密存储、启动时仅解密到内存；
2. License 客户端、License Server、设备绑定、签名许可证、离线宽限和最小管理后台。

现有快手 Cookie 已有完整透传路径，所以当前没有修改平台解析器、监控、录制器或 FFmpeg 链路的理由。建议将这些目录作为 V1 冻结区：

- `app/core/platforms/**`
- `app/core/recording/**`
- `app/core/media/**`

## 6. 平台内置登录的最小文件范围

建议新增 6–8 个旁挂文件：

```text
app/commercial/login/
├─ __init__.py
├─ platform_profiles.py
├─ webview_login.py
├─ cookie_service.py
└─ login_service.py
app/commercial/security/
├─ __init__.py
└─ dpapi_store.py
app/ui/views/platform_login_view.py
```

预计最小修改 5–7 个现有文件：

- `app/app_manager.py`：注册服务与页面；
- `main.py`：增加路由；
- `app/ui/navigation/sidebar.py`：增加平台登录入口；
- `app/ui/views/settings_view.py`：快手改为“已登录/重新登录”，停止保存明文；
- `pyproject.toml` / `requirements.txt`：WebView2 依赖；
- `scripts/build.py`：收集 WebView2 依赖；
- 两份 locale 文案按需要调整。

登录成功后，解密得到的 Cookie 只注入 `settings.cookies_config["kuaishou"]` 的内存状态，不调用现有 `save_cookies_config`，因此快手 handler 和录制链路不变。

Flet 本身能否稳定读取 WebView2 HttpOnly Cookie 仍为 D。第一实现切片应先做一个 WebView2 Cookie API 探针；若 Python 组件不支持，再使用小型原生 WebView2 helper，仍保持旁挂。

## 8. 核心修改审批判断

当前判断：不需要修改核心。

唯一需要继续观察的风险是 `PlatformHandler._instances` 缓存键不含直播间 URL/任务 ID；同平台、同 Cookie、同画质任务可能共享 handler 和 `streamget` 实例，见 `base.py:62-75,107-124`。这只是风险线索，不能直接作为改核心的理由。必须先用三个快手直播间复现串流或竞态，才能提交核心修改审批说明。

若复现，审批材料至少包含：复现输入、日志和输出文件证据、外围隔离为什么无效、拟修改文件、并发/单房/其他平台回归项。审批前不改核心。

## 10. 发布与验收风险

1. 成品 `StreamCap.exe` 未数字签名，Windows 商业发布需要代码签名与信誉积累。
2. 当前依赖多为 `>=` 且没有 lock/hash，构建不可复现；商业发布前必须锁定版本。
3. 当前成品与 `scripts/build.py`/打包文档的资源布局存在差异，需干净机验证。
4. 发布包必须自动断言包含 LICENSE、第三方开源清单，并且不含 `.env`、私钥、开发 Cookie。
5. 商业版更新源必须切到自有 `/v1/app/version`，避免把用户导向上游免费版。
6. 普通日志不得包含 Cookie、激活码和许可证原文。`play_url.log` 可能记录带临时签名的流地址，需单独评估；若要改核心日志，必须走审批。
7. License Server 私钥只能存在服务端 secret；客户端只携带公钥。
