# 录播达人部署与验收说明

## 客户端发布配置

Windows 发布前必须配置以下环境变量：

- `LICENSE_SERVER_URL`：授权服务 HTTPS 地址；
- `LICENSE_PUBLIC_KEY`：与服务端私钥配套的 Ed25519 公钥，客户端把它作为固定信任根；
- `LICENSE_REQUIRED=true`：启用启动门禁；
- `LICENSE_OFFLINE_GRACE_DAYS=7`：与服务端离线宽限保持一致；
- `UPDATE_SOURCE=custom`：更新只查询自有版本接口。

本地开发允许 `http://localhost` 或 `http://127.0.0.1`，其他地址必须使用 HTTPS。`LICENSE_REQUIRED=false` 只用于开发调试，正式包不得关闭授权。

执行 `python scripts/build.py --platform windows` 生成 `dist/LuboDaren/`。构建脚本会带入 FFmpeg、Node.js、WebView 登录依赖，并把 `LICENSE` 和 `THIRD_PARTY_NOTICES.md` 放在发布目录顶层。

## 授权服务

进入 `license-server`，复制 `.env.example` 为 `.env`，为数据库密码、管理令牌、激活码摘要 pepper 和 Ed25519 私钥分别生成独立随机值。生产环境通过 HTTPS 反向代理暴露服务，数据库和容器端口不直接开放到公网。

启动命令：

```text
docker compose up --build -d
```

容器启动时自动执行数据库迁移。管理页面位于 `/admin`，支持批量生成和一次性导出激活码、搜索、查看绑定设备与事件、禁用、解绑和版本配置。

## 已完成的自动验收

- Python 客户端测试、静态检查和字节码编译；
- TypeScript 类型检查、Jest 测试和 NestJS 生产构建；
- Python 与 TypeScript 的确定性 Ed25519 签名契约；
- Windows DPAPI 加密落盘，磁盘文件不含 Cookie 明文；
- 旧快手 Cookie 从普通配置迁移后，普通 `cookies.json` 被清除；
- 未激活时不启动录制调度，激活成功后才恢复登录态并启动调度；
- Windows onedir 包含 FFmpeg、Node.js、WebView2 适配文件、LICENSE 和第三方声明；
- Windows 10 22H2 本机启动成功，窗口标题为“录播达人”且保持响应。

## 发布前仍需人工验收

下列项目需要真实账号、真实直播间或独立干净机，不能用模拟测试代替：

1. 快手官方页面扫码登录，确认实际账号 Cookie 可被 WebView2 API 获取；
2. 未播到开播、自动录制、下播保存及 MP4/TS 实际播放；
3. 至少三个真实直播间并发监控与录制；
4. Windows 10 与 Windows 11 x64 干净机安装、启动和 WebView2 环境检查；
5. 生产 HTTPS、PostgreSQL 备份、管理令牌轮换以及最终代码签名；
6. 发布前对目标平台规则、录制内容授权和最终 FFmpeg 构建许可证再核对一次。
